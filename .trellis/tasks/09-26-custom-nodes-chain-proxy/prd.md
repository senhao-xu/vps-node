# 自定义节点与链式代理（父任务）

## Goal

为面板增加两类节点扩展能力，本身不直接实现，拆分为两个独立验收的子任务：

1. **自定义节点**（子任务 `09-26-custom-nodes`）：管理员维护外部分享链接/订阅 URL，**按用户授权**（与托管节点一致）后并入对应用户的订阅输出。
2. **链式代理**（子任务 `09-26-chain-proxy`）：托管节点可选择另一个托管节点作为出站，流量经 sing-box 出站转发。

## 子任务地图

| 子任务 | 交付物 | 独立验收 |
| --- | --- | --- |
| 09-26-custom-nodes | custom_nodes 表、订阅渲染合并、URI 解析器、管理 UI | 订阅输出包含自定义节点 |
| 09-26-chain-proxy | nodes.chain_node_id、sing-box 出站渲染、relay 凭证、管理 UI | 入口节点流量经出站节点落地 |

## 跨子任务验收标准

- [ ] 两个子任务可独立交付、独立回滚（DB migration 分开、互不依赖）
- [ ] 自定义节点与链式代理可同时存在：链式入口节点照常出现在订阅中，自定义节点照常追加
- [ ] `make build`（vet + test + build）通过

## Out of Scope（父任务级）

- 终端用户自助上传自定义节点（本期仅管理员维护，按用户授权分发）
- 自定义节点的流量统计 / 在线设备（外部节点无测量点；已评估：A=上游 userinfo 透传仅账号粒度，B=作为链式出站端可统计，本期均不做，留作 backlog）
- 链式代理的负载均衡 / 多出口轮询（本期单出站）
