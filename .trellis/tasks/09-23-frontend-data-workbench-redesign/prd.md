# 按数据工作台方案重构前端

## Goal

将 `web/` 管理后台整体重构为数据工作台：使用左侧主导航、紧凑指标栏、表格优先的工作区和异常辅助区，使用户、服务器、节点和访问记录的日常管理更高效；同时强化详情页返回与资源身份层级，打磨全站共享细节，并保留现有业务能力与数据契约。

## Background / Confirmed Facts

- 前端技术栈为 Vue 3.5、TypeScript strict、Vite 7、Pinia、Vue Router 和 `lucide-vue-next`；没有通用 UI 框架。
- 现有路由覆盖登录、仪表盘、用户、用户详情、服务器、服务器详情、节点、访问记录、设置和 404。
- 重构前的应用采用固定侧边栏、顶部工具栏、统计卡片和表格组合；当前工作树已实现用户最初批准的顶部导航版 B 数据工作台，但用户基于实际页面截图要求将导航改回左侧栏，同时保留紧凑汇总、表格主导、异常辅助和 teal 视觉语言。
- 现有 API 已提供仪表盘汇总、用户流量、用户、服务器、节点、访问记录和设置数据；本次可在前端组合现有请求，不需要新增业务数据模型。
- 现有 API 不提供昨日流量增幅、持续高负载时长或全局 Agent 同步时间；界面必须使用可验证的当前快照与“状态最近刷新时间”，不得照抄预览中的示意数据。
- 项目已有语义 token、暗色主题、共享表格、分页、弹窗、状态徽章、筛选与溢出菜单组件，重构应在这些所有权边界上演进。

## Requirements

### R1 - B 方案成为全站视觉基线

- 桌面端应用壳层使用左侧品牌区与垂直主导航，内容区顶部保留紧凑工具栏。
- 左侧栏或内容工具栏提供紧凑系统状态，承载 Panel、服务器在线数、状态最近成功刷新时间和构建版本等全局状态，不恢复旧版卡片化状态墙。
- 采用中性灰白表面、墨色正文、青绿色主操作色、红/琥珀/绿色状态色；圆角、阴影和装饰保持克制。
- 页面以紧凑标题、行内指标和工作区为主，不使用营销式大标题、同权重卡片墙或无业务价值的装饰。

### R2 - 导航与响应式布局

- 桌面端使用固定展开的 `216px` 左侧导航，完整覆盖仪表盘、用户、服务器、节点、访问记录和设置；不提供折叠按钮，也不持久化折叠状态。
- 内容区顶部保留菜单搜索、主题切换、管理员身份与退出能力；全局路由不再占用顶部横向空间。
- `<900px` 时左侧导航切换为可关闭的抽屉，不隐藏任何现有路由，并具备菜单触发器、遮罩点击关闭、Escape 关闭、背景滚动锁、路由切换后关闭和触发器焦点恢复。
- 支持 320、375、560、700 和桌面宽度；页面本身不得产生意外水平溢出，宽表格只能在有语义标签的表格区域内滚动。
- 保留浅色、深色和跟随系统三种主题模式。

### R3 - 仪表盘重构为运营工作台

- 首屏展示紧凑的用户、今日流量、在线设备、服务器和节点汇总，不再铺设六张同权重统计卡。
- 用户流量表成为主工作区，保留今日/累计切换、配额进度和节点明细能力。
- 右侧或相邻区域集中呈现离线服务器、高负载等需要关注的资源；数据由现有仪表盘和分页服务器接口组合，必须覆盖完整服务器集合，不新增后端接口。
- 只展示现有 API 能证明的当前状态和指标，不展示虚构的同比、持续时长或协议总类数。
- 主要动作、异常和数据表的视觉优先级高于说明文字与辅助元数据。

### R4 - 列表页与详情页统一

- 用户、服务器、节点、访问记录页采用一致的紧凑工具栏、筛选、批量操作、表格、分页和异常/空/加载状态。
- 服务器列表不再重复铺设大面积统计卡；关键汇总收敛为行内指标或紧凑状态栏。
- 用户详情与服务器详情使用紧凑资源头、分区信息和高密度数据视图；不嵌套装饰性卡片。
- 设置页、登录页、404 和全部业务弹窗跟随同一套色彩、排版、控件密度与状态语言。

### R5 - 交互、可访问性与一致性

- 保留现有搜索、筛选、排序、选择、批量启停、复制、删除确认、主题、快捷键和分页行为。
- 图标统一使用 Lucide；图标按钮提供可访问名称，表单和弹窗保留键盘、焦点管理与错误反馈能力。
- 所有动态状态具备清晰的加载、空数据、错误、禁用和进行中表现。
- 共享视觉规则优先落在 `styles/tokens.css`、`styles/base.css` 和共享 UI 组件，页面只保留业务特有布局。

### R6 - 技术与兼容边界

- 不改变后端 API、路由 URL、鉴权流程、Pinia 状态契约和核心业务行为。
- 不引入大型 UI 框架；继续使用现有 Vue 组件体系和 `lucide-vue-next`。
- 保持 TypeScript strict，不新增 `any`，API 类型继续由 `web/src/api/types.ts` 单点拥有。

### R7 - 详情层级与全站细节打磨

- `PageHeader` 的详情返回入口升级为清晰的图标加文字按钮，用户详情显示“返回用户列表”，服务器详情显示“返回服务器列表”；键盘焦点与窄屏换行必须保持可用。
- 用户详情将返回、用户名、状态、ID/授权节点元数据和指标条形成清晰的资源头，不让状态孤立在超宽页面右侧；现有基本信息、流量、有效期、限制、设备、节点授权、趋势和访问功能保持不变。
- 其他认证页面进行受控的共享细节打磨：页面标题与主操作对齐、卡片/工作区标题层级、工具栏密度、空/错/加载状态、长文本截断、暗色对比和移动端间距保持一致。
- 细节打磨优先修改 `PageHeader`、`AppLayout`、tokens/base 和已有共享组件；不借机改业务请求、字段、路由或重新组织后端数据。

## Acceptance Criteria

- [ ] AC1：登录后所有认证路由采用左侧主导航与数据工作台视觉语言；桌面侧栏固定展开为 `216px` 且无折叠状态，`<900px` 时通过可关闭抽屉访问全部路由。
- [ ] AC2：仪表盘首屏呈现紧凑汇总、用户流量主表和需要关注区域；不再出现六张同权重统计卡墙。
- [ ] AC3：用户、服务器、节点和访问记录页的工具栏、表格、分页、批量操作及状态反馈一致，现有操作行为无回归。
- [ ] AC4：用户详情、服务器详情、设置、登录、404 和业务弹窗完成同一视觉系统迁移，无遗留旧主题页面。
- [ ] AC5：浅色、深色和系统主题均可用；320 / 375 / 560 / 700 / 桌面宽度无文本遮挡或页面级横向溢出，宽表格仅在其可访问滚动区内滚动。
- [ ] AC6：菜单搜索、键盘焦点、弹窗焦点陷阱、错误提示、图标按钮可访问名称及 reduced-motion 行为继续有效。
- [ ] AC7：`cd web && npm run typecheck && npm run lint && npm run build` 全部通过，并完成主要页面的桌面/移动端截图核对。
- [ ] AC8：前端改动不要求后端 API、数据库或部署配置迁移。
- [ ] AC9：状态条和异常面板中的时间、版本、健康与趋势文案均与现有数据语义一致，不把 UI 刷新时间描述为 Agent 同步时间，不展示 API 不支持的历史趋势。
- [ ] AC10：用户详情和服务器详情的返回入口在浅色/暗色及 320px 宽度下都具备清晰按钮外观、明确目标文案和可见焦点；用户详情资源身份与状态在首屏形成一个视觉组。
- [ ] AC11：所有认证页面完成共享细节复核，不出现旧顶部横向导航残留、文本遮挡、页面级横向溢出、双重边框或不一致的标题/工具栏间距。

## Out of Scope

- 后端 API、数据库、Agent 与 sing-box 运行时改动。
- 新增权限系统、通知中心、业务报表或其他当前不存在的产品功能。
- 为流量同比、高负载持续时长或全局同步时间新增后端历史/聚合接口。
- 引入通用 UI 框架、图表框架或 i18n 框架。
- 将管理表格改成移动端卡片列表。

## Key Decisions

- 用户选择 B「数据工作台」作为全站方向，而不是仅改仪表盘。
- 用户最新决定将全局导航从顶部横向导航改回左侧栏；紧凑指标、表格主导和异常辅助仍是数据工作台的验收重点。
- 桌面侧栏固定展开为 `216px`，不增加折叠入口或本地持久化状态；`<900px` 时切换为移动端抽屉。
- 保留现有业务行为、浅/深/系统主题和前端技术栈；通过共享 token 与组件完成迁移。
