# 用户订阅链接

## Goal

让管理员能在用户详情页获取并复制一个可直接导入客户端的订阅链接，使终端用户获得其已授权且当前可用的节点配置，无需管理员逐个手工拼接协议参数。

## Background

- 原始产品需求将订阅链接列为第一版之后的扩展能力（`demand.md:1309`），现有 API 合约和路由尚未定义订阅端点。
- 用户已有随机 Token，但数据库仅保存 `token_hash`；明文 Token 只在创建或重置时返回一次，因此后台不能为已有用户恢复旧 Token 或直接重建包含该 Token 的链接。
- 用户详情页目前只允许显式重置 Token，并通过一次性秘密组件展示新 Token。
- 用户与节点是多对多授权关系；节点通用 DTO 不包含协议秘密，而生成客户端配置需要安全读取节点协议设置。
- 用户状态、有效期和流量配额已有统一 eligibility 规则，订阅行为必须明确如何应用这些限制。
- 本任务仅参考 XBoard 的订阅链接体验：单一 `/<subscribe_path>/<token>` URL、可配置订阅基地址与路径、根据 `User-Agent` 或 `flag` 选择客户端格式，以及后台随时复制同一 URL。XBoard 的明文用户 Token、完整 Clash 模板、正则代理组注入和其他用户系统设计不作为本项目实现依据。研究见 `research/xboard-subscription-research.md`。

## Requirements

- R1. 管理员可在用户详情页看到订阅管理区域，并复制当前有效的订阅 URL。
- R2. 已有用户不需要重置现有用户 Token 才能创建订阅链接；订阅凭据与现有用户 Token 分离，避免影响搜索和其他未来用途。
- R3. 订阅凭据必须使用加密安全随机值；数据库保存用于公开端点鉴权的哈希，并使用现有 `app_key` 加密保存可恢复值，使管理员可在用户详情页随时复制当前链接。通用用户 DTO、日志和列表不得包含订阅凭据。
- R4. 公开订阅端点不要求管理员会话，以 URL 中的高熵订阅凭据鉴权，并且不得把凭据写入应用日志。
- R5. 订阅只包含该用户已授权的节点；用户被禁用、已过期或超过非零配额时不得返回可用配置。
- R6. 节点被禁用、所属 Server 被禁用或订阅所需连接信息不完整时不得输出不可用配置。
- R7. 管理员可明确轮换订阅链接，旧链接立即失效；不得静默轮换。
- R8. 订阅响应不得暴露 Panel/Agent 管理凭据、节点服务端私钥或其他用户信息。
- R9. UI 延续现有蓝白控制台样式，并在桌面和移动端都能复制链接、查看一次性凭据提示和执行轮换。
- R10. 参考 XBoard 使用单一订阅 URL；订阅端点可根据客户端 `User-Agent` 自动选择格式，并允许通过显式参数覆盖，避免为每种客户端维护不同凭据。
- R11. 首版订阅输出两种格式：默认通用 Base64 协议链接集合，以及 Clash Meta YAML；首版不提供 sing-box JSON。
- R12. Clash 覆写是本项目独立设计的一份全局受限 Clash Meta 模板，不要求兼容 XBoard 模板语义。管理员可配置 DNS、代理组、规则、规则集和明确允许的基础运行参数；模板不得提供或改写 `proxies`、`proxy-providers`、节点地址与凭据、监听器、外部控制接口或认证信息。服务端完成模板校验后强制注入当前用户符合条件的动态节点。
- R12.1. Clash Meta 代理组使用明确占位符注入动态节点：`__ALL_PROXIES__`、`__SHADOWSOCKS_PROXIES__`、`__VLESS_PROXIES__`、`__HYSTERIA2_PROXIES__`。没有占位符的组保持其静态策略和其他组引用，不自动追加节点；不支持 XBoard 正则注入语义。
- R13. Hysteria2 节点补充完整 TLS 配置，使 Agent 入站和客户端订阅使用一致的证书身份。管理员创建或更新节点时提供 `server_name`、PEM 证书链和匹配私钥；Panel 校验证书/私钥匹配和证书对 `server_name` 的主机名有效性，将私钥与证书材料按协议秘密加密保存，并通过现有 Agent 配置通道以内联 TLS 材料下发。客户端订阅默认执行严格证书验证，不输出 `insecure=1`。
- R14. Hysteria2 证书续期由管理员显式上传替换证书和私钥；成功替换触发所属 Server revision，失败校验不得修改现有节点配置。
- R15. 新建用户时自动生成独立订阅凭据，创建响应同时提供可复制的订阅 URL。迁移不为历史用户批量创建长期凭据；既有用户首次在详情页由管理员显式生成，之后可随时复制或轮换。
- R16. 订阅 URL 基地址与 XBoard 一致：设置页提供可选的 `subscribe_url`，支持多个逗号分隔的绝对 HTTP(S) 基地址；生成链接时从已配置地址中选择一个并拼接订阅路径。未配置时回退到当前请求的站点 Origin。订阅路径可配置，默认 `s`，并校验为安全的单一路径段。
- R17. 请求日志必须将订阅 URL 中的凭据路径段替换为固定占位符；日志、错误消息和指标标签不得包含订阅 Token。

## Constraints

- 保持 Panel、Server、Node、Agent 的现有职责边界，不改变 Agent 配置同步协议。
- 继续使用 Go 标准库优先、Vue API 类型集中管理和既有错误信封约定。
- 订阅 URL 属于持有即授权的秘密；通用请求日志不得记录 URL 查询串或凭据。
- 本任务需要新增公开端点、持久化订阅凭据和客户端配置渲染，属于复杂跨层任务，必须具备 `design.md` 和 `implement.md` 后才能开始实现。

## Out of Scope

- 用户自助登录页面、设备管理、设备数限制和订阅使用审计。
- 自动修改防火墙、DNS、TLS 证书或节点端口。
- ACME 自动签发、自动续期、Panel 生成自签证书，以及仅依赖 Agent 本地证书路径的外部证书管理。
- 为未授权节点或不满足 eligibility 的用户生成配置。
- 在列表或通用用户 DTO 中返回明文订阅凭据。
- 用户级 Clash 模板、用户通过订阅 URL 提交覆写内容，以及任意完整 YAML 模板。

## Acceptance Criteria

- [ ] 新建及已有用户都可由管理员生成订阅链接，无需修改用户业务 Token。
- [ ] 新建用户创建成功时即可交付订阅链接；历史用户升级后保持无订阅凭据，直到管理员首次显式生成。
- [ ] 配置一个或多个订阅基地址时，生成的链接使用配置地址；未配置时使用当前站点 Origin；无效协议、含凭据的 URL 或非法订阅路径无法保存。
- [ ] 用户详情页可随时查看并复制当前完整订阅 URL；该 URL 不进入用户列表或通用用户 DTO。
- [ ] 轮换后旧链接立即不可用，新链接可访问。
- [ ] 订阅只输出符合用户状态、有效期、配额、节点和 Server 状态约束的授权节点。
- [ ] 无效凭据、被禁用、已过期和超额用户不会获得可用节点配置。
- [ ] 响应中不出现 Reality 私钥、服务端 Shadowsocks 密码、管理 Token 或其他用户数据。
- [ ] 管理员可在设置页编辑和恢复全局 Clash Meta 模板；无效 YAML、禁止字段或无效代理组/规则引用无法保存。
- [ ] 模板无法增加静态代理或修改服务端生成的节点地址、端口和凭据。
- [ ] Clash Meta 代理组按四种明确占位符注入全部或指定协议节点；无占位符的组不被隐式修改。
- [ ] Hysteria2 缺少证书、私钥或 `server_name`，证书与私钥不匹配，或证书不覆盖 `server_name` 时无法创建或替换配置。
- [ ] Hysteria2 Agent 配置包含匹配的 TLS 证书材料，通用节点 DTO 和订阅响应不包含私钥；客户端订阅使用 `server_name` 且不跳过证书验证。
- [ ] 访问订阅端点后，应用日志中不出现订阅 Token。
- [ ] API、仓储、迁移、渲染器和前端交互具备自动化测试。
- [ ] Go 全量测试、race 测试、嵌入式 UI 构建及 Web typecheck/build/lint 通过。
