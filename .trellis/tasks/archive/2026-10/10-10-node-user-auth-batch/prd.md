# PRD: 节点维度批量授权用户

## 背景

当前授权模型是「用户 × 节点」（`user_nodes` 表），唯一管理入口在用户详情页的「节点授权」卡片。新建节点后，必须逐个进入每个用户详情页勾选保存，用户多时极其繁琐。

## 目标

提供**节点维度**的授权管理入口：在节点列表行操作中新增「用户」按钮，弹窗展示全部用户及该节点的授权状态，支持批量勾选/全选后一次性保存。

## 需求

1. 节点列表每行操作区新增「用户」图标按钮，点击打开授权弹窗。
2. 弹窗展示所有用户（含 disabled），每行复选框表示该用户是否被授权此节点：
   - 显示用户名、状态、到期时间、当前已授权节点数
   - 顶部提供「全选 / 全不选」
   - 已授权 / 已选数量统计
3. 保存采用**全量覆盖**语义（与用户侧 `PUT /api/users/{id}/nodes` 对称）：提交的列表即该节点最终授权用户集合。
4. 保存成功后 agent 配置 revision 正确递增，节点同步即时生效（复用现有 bump 机制）。
5. dirty 检测：未修改时禁用保存按钮；保存后显示已保存反馈。

## 非目标

- 不引入 server 级授权表或自动授权开关（后续可选迭代）。
- 不改变用户详情页既有授权交互。
- 不做用户列表分页（管理面板用户量级小，全量返回）。

## 验收标准

1. `GET /api/nodes/{id}/users` 返回 `{user_ids, users}`；`PUT /api/nodes/{id}/users` 全量覆盖并 bump 该节点所属 server 的 revision。
2. `user_ids` 含不存在用户 → 400；请求体缺 `user_ids` 字段 → 400（与用户侧一致）；节点不存在 → 404。
3. 弹窗内勾选变化 → 保存 → 重新打开弹窗状态正确；对应订阅输出与 agent 配置同步变化。
4. 撤销授权后该用户订阅不再包含此节点（对齐 `internal/web/agent_revocation_test.go` 既有行为）。
5. `go test ./...`、`npm run typecheck && npm run lint && npm run build`、`npm test` 全部通过。
